Proofline Field Trials Register

Objective

Create a durable Proofline field-trials register that consolidates real-task evidence and identifies the next field-test task.

Acceptance Object

The work is acceptable when docs/proofline-field-trials.md records the field-trial counting rules, current evidence, current readout, and next field-test task, and the run renders status and closeout from passing checks.

Constraints

  • Count only repo-backed Proofline catches, not chat-only impressions.
  • Keep optimizer/candidate/evaluation/replay tooling separate from core field trials unless explicitly tested.
  • Do not claim ownership of unrelated dirty worktree changes.
  • Do not expose secrets or environment values in artifacts.

Core Proofline Workflow

Use this path for real scoped work.

  1. Add explicit requirements to this task and MANIFEST.json deliverables.
  2. Add required checks and evidence paths in MANIFEST.json.
  3. Execute checks and write evidence with: 
    python3 scripts/run_checks.py runs/proofline-field-trials-register/MANIFEST.json --root .
  4. Validate manifest contracts: 
    python3 scripts/lint_manifest.py runs/proofline-field-trials-register/MANIFEST.json --root .
python3 scripts/verify_manifest.py runs/proofline-field-trials-register/MANIFEST.json --root .
  5. Render closeout artifacts: 
    python3 scripts/run_status.py runs/proofline-field-trials-register/MANIFEST.json --root . --output runs/proofline-field-trials-register/artifacts/status.html
python3 scripts/closeout_check.py runs/proofline-field-trials-register/MANIFEST.json --root . --output runs/proofline-field-trials-register/artifacts/closeout.html
  6. Run repository gate when the work is complete: 
    python3 scripts/check_repo.py

Policy Modules

List any active harness policy modules from harness/policies/. Policy modules describe strategy; deterministic scripts still own exact validation and scoring.

Trace Ledger

Proofline core runs use runs/proofline-field-trials-register/TRACE.jsonl for raw events. Validate it with scripts/lint_trace.py before closeout.

Mechanism Metrics

Research runs can derive mechanism metrics with scripts/trace_metrics.py. Use them to inspect harness behavior; keep manifest validation and closeout evidence as the source of completion truth.

When Not to Use Proofline

  • One-line typo fixes.
  • Trivial local-only edits with no durable handoff.
  • Throwaway experimentation with no evidence dependency.

Risks And Blockers

  • Over-counting Proofline value would make the field trial dishonest.
  • Promoting optimizer tooling from core Proofline wins would blur the product boundary again.
  • Starting Capsule implementation before an implementation plan would skip the next planned field-test step.
