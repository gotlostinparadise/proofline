CIPH Task

Objective

Implement CIPH v0.22 Replay Result Attestation: persist normalized replay receipts for dry-run and executed evaluator replays with command digest, sandbox mode, timeout, env allowlist names, pre/post output hashes, status, docs, Proofline bundle sync, and dogfood evidence.

Acceptance Object

Accepted when replay dry-runs and local executions write normalized JSON receipts, receipts contain command digest, sandbox mode, timeout, env allowlist names, pre/post output hashes, status, and report path, receipts avoid environment values and command output content, bundled and installed Proofline assets are synchronized, the dogfood run closes out, and the repository gate passes.

Constraints

  • Keep replay execution opt-in and fail-closed.
  • Do not record environment values, command stdout, or command stderr in receipts.
  • Do not add provider/API execution or trusted signing.
  • Keep receipts derived from local replay metadata and local execution results.
  • Mirror workflow changes into bundled and installed Proofline skill assets.

Volatile Facts To Verify

No external volatile facts are required. This slice depends on local CIPH schemas and Python standard-library JSON, hashing, time, path, and subprocess behavior.

Policy Modules

Active modules: state, context, verification, recovery, delegation, candidate-search, and stopping.

Trace Ledger

Research runs use runs/ciph-v0.22-replay-result-attestation/TRACE.jsonl for raw events. Validate it with scripts/lint_trace.py before closeout.

Mechanism Metrics

Research runs can derive mechanism metrics with scripts/trace_metrics.py. Use them to inspect harness behavior; keep manifest validation and closeout evidence as the source of completion truth.

Risks And Blockers

  • Receipts can become misleading if dry-run and execution statuses are not explicit.
  • Command output and environment values may contain secrets and must stay out of receipts.
  • Receipts prove local replay status, not evaluator trust or cryptographic authenticity.
