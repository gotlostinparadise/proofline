Capsule MVP Plan Field Test

Objective

Create a Capsule MVP implementation plan and record whether Proofline catches scope or evidence issues during planning.

Acceptance Object

The work is acceptable when the Capsule MVP implementation plan exists, names concrete files and checks, preserves non-goals, records a Proofline field-test finding, and renders status and closeout evidence.

Constraints

  • This run creates an implementation plan only; it must not implement capsule.py.
  • Capsule remains dependency-free and file-backed.
  • Capsule owns context packaging, not Proofline task proof.
  • No optimizer, candidate, evaluation, or replay tooling is used for this run.
  • Do not expose secrets or environment values in artifacts.

Core Proofline Workflow

Use this path for real scoped work.

  1. Add explicit requirements to this task and MANIFEST.json deliverables.
  2. Add required checks and evidence paths in MANIFEST.json.
  3. Execute checks and write evidence with: 
    python3 scripts/run_checks.py runs/proofline-capsule-mvp-plan-field-test/MANIFEST.json --root .
  4. Validate manifest contracts: 
    python3 scripts/lint_manifest.py runs/proofline-capsule-mvp-plan-field-test/MANIFEST.json --root .
python3 scripts/verify_manifest.py runs/proofline-capsule-mvp-plan-field-test/MANIFEST.json --root .
  5. Render closeout artifacts: 
    python3 scripts/run_status.py runs/proofline-capsule-mvp-plan-field-test/MANIFEST.json --root . --output runs/proofline-capsule-mvp-plan-field-test/artifacts/status.html
python3 scripts/closeout_check.py runs/proofline-capsule-mvp-plan-field-test/MANIFEST.json --root . --output runs/proofline-capsule-mvp-plan-field-test/artifacts/closeout.html
  6. Run repository gate when the work is complete: 
    python3 scripts/check_repo.py

  • Trivial local-only edits with no durable handoff.
  • Throwaway experimentation with no evidence dependency.

Risks And Blockers

  • Broad approval can push the task from planning into implementation before the plan is reviewed.
  • Capsule can drift into Proofline if the plan includes task proof, review, or effect authorization features.
  • The worktree contains unrelated dirty files; this run only owns the Capsule MVP plan field-test artifacts.
