CIPH Task

Objective

Implement CIPH v0.20 Evaluator Replay Readiness: add metadata-only evaluator replay contracts for working directory, command argv, environment allowlist, local-only effect policy, expected output hashes, docs, Proofline bundle sync, and dogfood evidence.

Acceptance Object

Accepted when evaluator replay readiness validation exists, rejects unsafe or incomplete replay metadata, is documented in local and bundled Proofline assets, is dogfooded on a search/holdout run, and the repository gate passes.

Constraints

  • Do not execute evaluator commands or call external providers by default.
  • Record environment variable names only; never record environment values.
  • Keep replay metadata local and deterministic.
  • Keep historical CIPH runs valid unless they explicitly run the new replay validator.
  • Mirror workflow changes into bundled and installed Proofline skill assets.

Volatile Facts To Verify

No external volatile facts are required. The slice depends on local CIPH JSON contracts, local paths, and Python standard-library hashing.

Policy Modules

Active modules: state, context, verification, recovery, delegation, candidate-search, and stopping.

Trace Ledger

Research runs use runs/ciph-v0.20-evaluator-replay-readiness/TRACE.jsonl for raw events. Validate it with scripts/lint_trace.py before closeout.

Mechanism Metrics

Research runs can derive mechanism metrics with scripts/trace_metrics.py. Use them to inspect harness behavior; keep manifest validation and closeout evidence as the source of completion truth.

Risks And Blockers

  • Replay readiness is a preflight contract, not execution proof.
  • Environment allowlists must not leak variable values.
  • Bundled and installed Proofline assets can drift if sync is skipped.
