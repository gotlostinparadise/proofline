CIPH Task

Objective

Implement CIPH v0.15 Evaluation Protocol: search-set versus holdout discipline, baseline/frontier validation, evaluation reporting, docs, bundled Proofline asset sync, and dogfood closeout evidence.

Acceptance Object

The work is acceptable when EVALUATION.json validates search-set versus holdout discipline, candidate summaries expose evaluation status, bundled Proofline assets include the validator and docs, and the dogfood run closes with generated evidence for every required check.

Constraints

  • Repository rules: keep evaluation validation deterministic and read-only.
  • Files or areas in scope: scripts/, tests/, README.md, harness/, skills/proofline/, and this run directory.
  • Files or areas out of scope: model runners, benchmark execution, encrypted holdout stores, and provider APIs.
  • Permissions: local file edits, local test commands, commit/merge/push closeout.
  • Secrets handling: do not print private scenario payloads, tokens, headers, or environment secrets in reports.

Volatile Facts To Verify

No external API, pricing, product-limit, or provider configuration facts are needed. This milestone uses local filesystem contracts and Python standard-library behavior.

Policy Modules

Active modules: state, context, verification, recovery, delegation, candidate-search, and stopping.

Trace Ledger

Research runs use runs/ciph-v0.15-evaluation-protocol/TRACE.jsonl for raw events. Validate it with scripts/lint_trace.py before closeout.

Mechanism Metrics

Research runs can derive mechanism metrics with scripts/trace_metrics.py. Use them to inspect harness behavior; keep manifest validation and closeout evidence as the source of completion truth.

  • Evaluation validation must stay read-only and must not expose holdout results during search phase.
  • Candidate summaries must remain backward-compatible for older runs.
  • Bundled Proofline assets and installed skill must stay synchronized.
