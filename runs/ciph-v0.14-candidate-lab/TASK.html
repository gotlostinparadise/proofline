CIPH Task

Objective

Implement CIPH v0.14 Meta-Harness candidate lab: full candidate records, candidate validation/reporting, docs, bundled Proofline asset sync, and dogfood closeout evidence.

Acceptance Object

The work is acceptable when candidate initialization creates a full Meta-Harness record, candidate validation catches missing or inconsistent record files, validation can emit an HTML report, docs and bundled Proofline assets describe the workflow, and the dogfood run closes with generated evidence for every required check.

Constraints

  • Repository rules: keep candidate creation deterministic and validation read-only.
  • Files or areas in scope: scripts/, tests/, README.md, harness/, skills/proofline/, and this run directory.
  • Files or areas out of scope: model runners, automatic candidate proposers, and holdout scoring.
  • Permissions: local file edits, local test commands, commit/merge/push closeout.
  • Secrets handling: do not print tokens, headers, environment secrets, or private payloads in candidate records or evidence.

Volatile Facts To Verify

No external API, pricing, product-limit, or provider configuration facts are needed. This milestone uses local filesystem contracts and Python standard-library behavior.

Policy Modules

Active modules: state, context, verification, recovery, delegation, candidate-search, and stopping. Policy modules describe strategy; deterministic scripts still own exact validation and scoring.

Trace Ledger

Research runs use runs/ciph-v0.14-candidate-lab/TRACE.jsonl for raw events. Validate it with scripts/lint_trace.py before closeout.

Mechanism Metrics

Research runs can derive mechanism metrics with scripts/trace_metrics.py. Use them to inspect harness behavior; keep manifest validation and closeout evidence as the source of completion truth.
