# CIPH v0.1 Design

## Goal

Build a small, file-backed Complex Implementation Project Harness that makes complex coding work easier to scope, execute, verify, and close out without introducing a custom agent runtime.

## Scope

CIPH v0.1 is a manual-first harness. It provides durable templates, a natural-language runtime charter, a manifest format, and deterministic verification scripts. It does not spawn agents, optimize prompts, run benchmarks, or hide state in a service.

## Architecture

The harness is repo-native. A project run is represented by a task file, a JSON manifest, evidence artifacts, and logs under a run directory. Scripts read those files and verify whether the required artifacts and evidence exist.

The harness separates three concerns:

- `harness/` contains stable rules and operating procedure.
- `templates/` contains copyable task and manifest starting points.
- `scripts/` contains deterministic checks that can run in any repository with Python 3.

## Components

### Runtime Charter

`harness/runtime-charter.md` defines the rules every run follows: source-of-truth handling, fact verification, delegation boundaries, evidence promotion, secret redaction, and completion claims.

### Harness Procedure

`harness/CIPH.md` defines the lifecycle: intake, scope, design, execute, verify, and close. It also defines contracts for tasks, artifacts, facts, child work, verification, and stop conditions.

### Manifest

`templates/MANIFEST.json` defines the expected shape of a run manifest. The manifest lists deliverables, artifacts, evidence, checks, and open risks. Required artifacts must be present. Required evidence pointers must exist or be external source references.

### Manifest Verifier

`scripts/verify_manifest.py` validates a manifest and checks referenced local paths. It returns a non-zero exit code when required artifacts, checks, or evidence are missing.

### Closeout Checker

`scripts/closeout_check.py` prints a prompt-to-artifact checklist. It treats the manifest as the source of truth and clearly separates covered, weak, and missing requirements.

### Sample Run

`runs/example-harness-design/` dogfoods the harness against this repo's first artifact, `index.html`. It proves the harness can point at an existing artifact and record verification evidence.

## Data Flow

1. The operator copies `templates/TASK.md` and `templates/MANIFEST.json` into a run directory.
2. The operator records objective, deliverables, artifacts, checks, and evidence.
3. Implementation work creates or modifies the target artifacts.
4. `scripts/verify_manifest.py` validates manifest structure and local evidence paths.
5. `scripts/closeout_check.py` prints the final checklist for human review.

## Error Handling

The scripts should fail loudly for invalid JSON, missing required keys, empty required values, missing required artifacts, and missing required evidence. They should report every discovered issue in one run so the operator can repair the manifest without repeated trial and error.

## Testing

Use Python `unittest` with temporary directories. Tests cover:

- A complete manifest with existing artifact and evidence passes.
- Missing required artifacts fail.
- Missing required evidence fails.
- Closeout output includes requirement, artifact, evidence, and status rows.

## Non-Goals

- No agent scheduler.
- No automatic MCP calls.
- No hidden memory database.
- No benchmark optimizer.
- No dependency on third-party Python packages.
