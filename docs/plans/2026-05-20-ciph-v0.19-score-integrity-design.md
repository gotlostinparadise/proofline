# CIPH v0.19 Score Integrity Design

## Goal

Make score artifacts tamper-evident after evaluation. v0.18 proved which evaluator produced a score; v0.19 should prove that the evaluator's declared inputs, evidence, and outputs still have the same bytes.

## Options Considered

1. Add SHA-256 digests to evaluator manifests and validate them with a standalone script.
   This is the selected approach. It keeps historical runs valid, avoids execution-engine scope, and gives research runs a deterministic integrity check.

2. Embed a score file's hash inside the score file itself.
   This is self-referential and fragile. It also makes ordinary JSON editing awkward.

3. Add cryptographic signatures.
   Signatures are stronger, but they require key custody, rotation, and trust rules. This slice should stop at local tamper evidence.

## Contract

Evaluator manifests may include:

```json
"integrity": {
  "schema_version": "ciph.evaluator-integrity.v1",
  "algorithm": "sha256",
  "input_hashes": {
    "runs/my-run/artifacts/search-input.json": "sha256:<hex>"
  },
  "evidence_hashes": {
    "runs/my-run/artifacts/search-evidence.txt": "sha256:<hex>"
  },
  "output_hashes": {
    "runs/my-run/candidates/frontier/score.json": "sha256:<hex>"
  }
}
```

`scripts/validate_score_integrity.py` follows `EVALUATION.json`, loads each score's `score_provenance`, then loads the evaluator manifest and checks every declared input, evidence, and output path against the manifest digest maps. The script fails if integrity is missing, a path lacks a digest, a digest format is invalid, or bytes have drifted.

## Reporting

The validator writes an HTML/text report with `data-proofline-report="score-integrity"`. Existing score provenance and comparison reports remain readable for historical records; strict integrity is opt-in through the new validator and run checks.

## Non-Goals

- No evaluator command replay.
- No provider or benchmark execution.
- No cryptographic signing.
- No retroactive migration of historical runs.

## Testing

Use TDD for valid search/holdout integrity, missing integrity, missing digest, hash mismatch, unsupported algorithm, invalid digest format, and CLI HTML output. Dogfood must include both search and holdout evaluator manifests with hashes and an integrity report.
