# CIPH v0.24 Experience Diagnostics Design

## Objective

Add a second-stage read-only diagnostics view over `runs/*/MANIFEST.json`, traces, required checks, artifacts, and replay receipts so the harness can prioritize what to repair next.

## Boundary

`scripts/diagnose_experience_store.py` is deterministic and read-only over source records. It must not mutate manifests, traces, receipts, or evidence content. It can write only the requested output report file.

## Data Sources

- `runs/*/MANIFEST.json` (checks, deliverables, artifacts, objective)
- `TRACE.jsonl` (or default `run_dir/TRACE.jsonl`)
- `EVALUATION.json` (for evaluation readiness checks)
- `replay_receipts/*.json` (for replay execution status)
- `path_exists` checks from `scripts.verify_manifest`

## Outputs

The script emits schema `ciph.experience-diagnostics.v1` in JSON by default and HTML via `report_kind="experience-diagnostics"`. Output includes:

- prioritized findings with `id`, `severity`, `run_id`, `reason`, `evidence_paths`, and `recommendation_id`
- recommendation rollup with severity/confidence, affected run IDs, and suggested next action
- summary counters by severity and affected runs

## Severity model

Severity order is `low < medium < high`.

- **high**: missing traces/closeout, required checks failing/missing validation, required artifacts missing, executed replay failures
- **medium**: empty traces, missing required evidence, evaluation has candidates but no replay receipts, etc.
- **low**: TODO placeholders, incomplete stages, dry-run-only replay

## Non-Goals

No new data persistence layer, no score-model changes, no external index, and no secret/evidence body serialization.
