# CIPH v0.23 Queryable Experience Store CLI Design

## Objective

Make accumulated CIPH run evidence searchable without introducing a mutable database. The experience store is a deterministic projection over `runs/*/MANIFEST.json`, `TRACE.jsonl`, generated check evidence, closeout events, and replay receipts.

## Boundary

`scripts/query_experience_store.py` is read-only. It must not rewrite manifests, traces, receipts, or generated evidence. It may write only the requested query report path.

## Record Shape

Each run record includes run id, objective, manifest path, trace path, event count, event types, stages, closeout status, deliverable and check counts, required artifact count, replay receipt paths and statuses, and selected evidence paths. The JSON envelope uses schema `ciph.experience-store.v1`.

## Query Surface

The first CLI supports deterministic filters that are useful for harness optimization:

- `--status PASS|FAIL|UNKNOWN` filters by closeout status.
- `--event-type <type>` filters by trace event type.
- `--contains <text>` searches run id, objective, event types, stages, and paths.
- `--has-replay-receipts` selects runs with replay receipt evidence.
- `--limit N` returns the newest lexical run ids after filtering.
- `--format json|html` emits machine-readable or reviewable output.

## Non-Goals

This milestone does not add embeddings, full-text indexing, external search backends, ranking models, or mutable annotations. Those belong after the local projection proves useful.
