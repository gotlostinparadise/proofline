# CIPH v0.22 Replay Result Attestation Design

## Objective

Persist normalized replay receipts for evaluator replay dry-runs and executions. CIPH v0.21 can execute approved local replay commands and verify output hashes, but the result is mostly represented by text/HTML reports. v0.22 makes replay status machine-readable and queryable for later optimizer milestones.

## Receipt Contract

Each replay command writes one JSON receipt under `runs/<run-id>/replay_receipts/`. Receipts use schema `ciph.replay-receipt.v1` and record evaluator ID, manifest path, execution mode, status, argv digest, sandbox mode, timeout, env allowlist names only, started/finished timestamps, report path, output byte counts, exit code, error messages, and pre/post output hash maps.

Dry-run receipts record `mode: "dry-run"` and do not execute commands. Executed receipts record `mode: "execute"` and the sandbox mode used by the executor. Receipts must never store environment values or command stdout/stderr content.

## Integration

`scripts/execute_evaluator_replay.py` owns receipt writing because it already discovers evaluator manifests, performs the readiness preflight, executes commands, and verifies hashes. The receipt writer should create deterministic filenames from evaluator ID and mode, so repeated dogfood runs refresh current evidence without proliferating files.

## Non-Goals

- No cryptographic signing or trusted timestamping.
- No provider/API execution.
- No new evaluator schema; receipts are derived execution artifacts.
- No separate receipt validator unless needed by tests or repo gate.
